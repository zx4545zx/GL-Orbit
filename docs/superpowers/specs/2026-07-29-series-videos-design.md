# Series Videos Design

**Status:** Approved

## Goal and Scope

Add ordered, bilingual YouTube videos to each series. Admins can add, delete, and reorder clips. The public series page groups clips by type and lets visitors select one to watch.

Initial types are `TRAILER` and `PILOT`. The design must allow another type through one application registry change, without altering the table type. Episode-level `trailer_url` remains unchanged and out of scope. Editing an existing video's metadata, drag-and-drop sorting, non-YouTube providers, uploads, analytics, and autoplay are also out of scope.

## Data Model

Add child table `series_videos`:

- `id`: UUID primary key, generated by default.
- `series_id`: required UUID referencing `series.id`, cascade on delete.
- `type`: required `varchar(32)`. Do not use a PostgreSQL enum or type check constraint; server validation is the extension point.
- `youtube_url`: required text containing the canonical watch URL.
- `youtube_video_id`: required `varchar(32)`, extracted only by server validation.
- `title_th`, `title_en`: required `varchar(255)` values, trimmed and non-empty.
- `sort_order`: required integer, default `0`, scoped to `(series_id, type)`.
- `created_at`: required timezone-aware timestamp, default now.

Add a unique constraint on `(series_id, youtube_video_id)` to prevent the same clip appearing twice for one series, plus an index on `(series_id, type, sort_order, created_at)` for ordered reads. Display order is `sort_order`, then `created_at`, then `id` for deterministic ties.

A shared application registry defines each accepted type's key, Thai/English label, and group order. It initially contains `TRAILER` before `PILOT`. Adding a future type updates this registry and translations, not the schema.

## Architecture and Data Flow

- Add a pure server YouTube parser/validator shared by all video mutations. It returns `{ canonicalUrl, videoId }`; clients never supply trusted IDs or embed URLs.
- Extend the admin full-series query and editor types with ordered `videos`.
- Add ADMIN-protected routes parallel to the gallery routes:
  - `GET/POST /api/admin/series/:id/videos`
  - `PUT /api/admin/series/:id/videos` for reorder
  - `DELETE /api/admin/series/:id/videos/:seriesVideoId`
- `POST` validates the parent series, type, titles, and URL, canonicalizes the URL, and appends at the end of that type group.
- `PUT` accepts `{ type, videoIds }`. The IDs must be unique and exactly match every current video in that series/type; reorder runs in one transaction and assigns contiguous values from zero. This prevents partial, cross-series, or cross-type reorder.
- `DELETE` scopes by both series ID and video row ID and returns `404` when no row matches.
- Extend `getSeriesDetail()` with one independent ordered video query. Return only trusted row fields and the stored `youtubeVideoId`; the browser does not parse arbitrary URLs.
- After successful video mutations, invalidate the affected `query:series:<seriesId>` cache entry so public data changes immediately.

## Validation and Errors

Accept HTTPS URLs in these exact forms, with an exact approved hostname and an 11-character YouTube ID matching `[A-Za-z0-9_-]{11}`:

- `youtube.com/watch?v=ID`, including `www.youtube.com` and `m.youtube.com`
- `youtu.be/ID`
- `youtube.com/shorts/ID`, including `www.youtube.com` and `m.youtube.com`

Reject HTTP, credentials, custom ports, lookalike/subdomain hosts, missing or malformed IDs, playlists without a video ID, unsupported paths, and non-YouTube URLs. Ignore tracking parameters and persist `https://www.youtube.com/watch?v=ID`. Validation performs no network request.

Mutation responses use stable codes with a safe admin message: `INVALID_TYPE`, `INVALID_TITLE`, `INVALID_YOUTUBE_URL`, `DUPLICATE_VIDEO`, `INVALID_REORDER`, `SERIES_NOT_FOUND`, and `VIDEO_NOT_FOUND`. Use `400` for invalid input, `403` for non-admin access, `404` for missing scoped resources, `409` for duplicates, and `500` only for unexpected failures. Keep submitted values on recoverable form errors; never expose database errors.

## Admin UX

Add a top-level **Videos** tab to the existing series editor, with its count. Use a focused manager component following current immediate-save gallery behavior:

- Add form: type select, Thai title, English title, and YouTube URL; all required.
- Group existing clips by type in registry order. Each row shows localized titles, canonical URL, type, and position.
- Up/down controls reorder only within the current type. Boundary controls are disabled. No drag-and-drop.
- Delete requires confirmation. Add, delete, and reorder are pessimistic, disable affected controls while pending, show success/error status, and refresh editor data after success.
- Empty state explains how to add the first clip. Controls retain visible focus, at least 44×44px targets, and square/rectangular Orbit Editorial styling.

## Public Series UX

Replace the current Trailer/Pilot mock placeholder section with real data. Hide the entire section when no videos exist.

- Show one type tab per non-empty group, in registry order.
- Default to the first clip in the first non-empty group. Changing type selects that group's first clip; clip buttons within the group let the visitor choose another clip.
- Display the active clip's title in the current language. Both titles are present, so no content-language fallback is needed.
- Render a responsive 16:9 iframe from the trusted ID only: `https://www.youtube-nocookie.com/embed/ID?playsinline=1&rel=0`.
- Do not autoplay when a clip or type is selected. Use lazy loading, a descriptive localized iframe title, `referrerpolicy="strict-origin-when-cross-origin"`, `allow="accelerometer; encrypted-media; gyroscope; picture-in-picture; web-share"`, and `allowfullscreen`.
- Never render `youtube.com/embed`, raw admin HTML, or a client-derived embed source. Type tabs expose correct selected state and panel relationships; clip selectors are keyboard-operable buttons with active state.

## Migration and Rollout

Generate one additive Drizzle migration after the current latest migration. It only creates `series_videos`, its foreign key, unique constraint, and ordered-read index. It does not backfill episode trailers, modify `series` or `episodes`, or delete data.

Review generated SQL and migration metadata, then test against an isolated/local database where available. Do not run `npm run db:push` or apply the migration to any configured database without explicit approval.

## Tests

- **Schema/migration:** fields, defaults, cascade foreign key, uniqueness, ordered index, and no changes to existing tables/data.
- **YouTube parser:** every accepted form, canonicalization/tracking removal, malformed IDs, unsafe protocols/credentials/ports, host lookalikes, playlists, and unsupported paths.
- **Admin API:** ADMIN guard on every method; parent/resource scoping; required titles/type; duplicate conflict; append order; exact-set transactional reorder; cross-series/type rejection; delete `404`; cache invalidation.
- **Queries:** admin and public shapes, registry group order, deterministic clip order, and deleted-series exclusion.
- **Admin component:** required fields, retained input on error, disabled/loading states, confirmation, boundary reorder controls, refresh after success, and accessible labels/focus.
- **Public page:** section absent when empty; non-empty type groups; default and changed selection; localized title; no autoplay; trusted `youtube-nocookie.com` source; no standard YouTube embed source; keyboard semantics.
- Run focused Vitest files, `npm run check`, `git diff --check`, and broader tests/build when implementation blast radius warrants them.

## Acceptance Criteria

1. One series can own multiple ordered videos, and deleting the series cascades to them.
2. Only registered types are writable; `TRAILER` and `PILOT` work initially, and adding another type needs no schema change.
3. Server-side validation accepts only the documented YouTube URL forms and persists canonical URL plus trusted video ID.
4. Both localized titles are required and shown in the matching public locale.
5. Every admin route independently requires ADMIN and scopes video operations to the requested series.
6. Admins can add, confirm-delete, and move clips up/down within a type, with clear pending, success, and error states.
7. Reorder rejects duplicate, missing, foreign-series, or foreign-type IDs and leaves existing order unchanged on failure.
8. The public page hides an empty video section; otherwise it groups by type, selects the first clip by default, and lets users switch type and clip.
9. Public embeds use only `youtube-nocookie.com`, trusted server-derived IDs, lazy loading, and no autoplay.
10. The migration is additive, does not backfill episode trailers, and is not applied without explicit approval.
